title: "독립적인 작업을 병렬로 진행하기"
description: "작업 범위와 worktree를 나누고 각 결과와 통합 결과를 검토합니다."
---

작업을 서로 독립적으로 진행할 수 있을 때 병렬 작업을 추가하세요. [에이전트 하나](/ko/quickstart)로 시작한 뒤 어떤 작업을 분리할 수 있는지 판단합니다.

## 작업 범위 나누기

각 에이전트에 목표, 관련 파일, 기대 결과, 검증 방법을 알려 주세요. 예를 들면 다음과 같습니다.

| 작업 | 범위 | 요청할 검증 근거 |
| --- | --- | --- |
| 검색 동작 구현 | 검색 코드와 단위 테스트 | 변경된 동작과 관련 테스트 결과 |
| 설치 안내 검토 | 문서만 검토하며 앱 코드는 수정하지 않음 | 확인한 명령과 오래된 안내 |

함께 정해야 하는 결정은 대화에서 다루세요. 작업들이 같은 파일을 건드리기 시작하면 서로의 작업을 덮어쓰기 전에 범위를 조정합니다.

## 각 작업에 worktree 만들기

1. **⌘N**을 누르고 프로젝트를 선택한 뒤 첫 작업을 설명합니다.
2. **Isolate in a dedicated worktree**를 켭니다. 감지된 프로젝트 setup 명령이 새 worktree에서 실행되며, 건너뛰려면 **Advanced**에서 **Run setup after creating**을 끕니다.
3. 에이전트를 시작합니다. 두 번째 작업은 다른 worktree로 반복합니다.
4. 같은 [Space](/ko/spaces-and-panes)에 pane을 나란히 배치합니다.

pane을 분할하거나 이동하면 배치가 바뀝니다. worktree가 자동으로 생기거나 파일이 이동하지는 않습니다. 수정 전에 각 에이전트의 작업 폴더를 확인하세요.

worktree는 작업 폴더와 브랜치를 분리합니다. 변경을 합칠 때 충돌할 수 있고, 같은 컴퓨터의 자격 증명, 프로세스, 포트, 네트워크 접근은 공유합니다.

## 검토하고 합치기

각 작업의 [diff](/ko/review-and-feedback)를 열어 변경과 검증 결과를 확인하세요. 필요한 피드백을 보낸 뒤 평소 Git 흐름으로 브랜치를 합칩니다. 겹친 변경을 해결하고 통합된 결과도 검증하세요.

작업 간 메시지나 명시적인 결정이 필요하면 [에이전트 조율](/ko/orchestration)을 사용하세요. 어떤 통합을 사용하든 사용자의 목표와 완료 기준은 분명해야 합니다.
