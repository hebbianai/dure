**GitHub** 사이드바에서 이슈, pull request, GitHub Projects를 볼 수 있습니다. 이슈를 새 대화에 직접 복사하지 않고 작업을 선택해 시작하세요.

## 저장소 연결

1. Mac에 GitHub CLI인 `gh`를 설치하고 저장소에 접근할 수 있는 계정으로 로그인합니다.
2. 해당 로컬 Git 폴더를 Dure 프로젝트로 추가합니다. remote가 의도한 GitHub 저장소인지 확인합니다.
3. 사이드바의 **GitHub**를 열고 저장소를 선택합니다.
4. **Issues**, **Pull requests**, **Projects** 중 하나를 선택하고 검색·필터·새로 고침을 사용합니다.

```sh
gh auth status
git remote -v
```

사이드바는 데스크톱의 GitHub 접근 권한을 사용합니다. 제공자 로그인과는 별개이며, 조직 접근에는 추가 권한이 필요할 수 있습니다. **Projects**에는 `read:project` 권한 범위가 필요합니다. 권한 오류가 표시되면 `gh auth refresh -s read:project`를 실행하세요. 이 권한이 없어도 Issues와 pull request는 사용할 수 있습니다.

## 이슈에서 에이전트 시작

작업 항목의 **Start**를 클릭하세요. 프로젝트, 에이전트 이름, 해당 이슈나 pull request에 대한 요청이 채워진 **New agent**가 열립니다. **Isolate in a dedicated worktree**는 꺼진 상태로 시작하므로 파일을 분리해야 하는 작업이라면 켜세요. 요청, 프로젝트, 제공자를 검토하고 필요하면 요청을 수정한 뒤 **Enter** 또는 **Start agent**로 시작합니다.

이슈의 경우 미리 채워진 요청은 에이전트가 먼저 현재 코드와 이슈를 대조하도록 합니다. 이슈가 이미 해결되었다면 요청에 따라 에이전트가 중복 변경 대신 완료 근거를 댓글로 남기고 이슈를 닫을 수 있습니다. 에이전트가 이슈를 변경하지 않기를 원한다면 시작하기 전에 요청을 수정하세요. pull request의 경우 요청은 남은 작업을 처리하고 리뷰를 준비하도록 하며, 에이전트를 시작해도 병합되지는 않습니다.

## 작업으로 돌아가기

연결된 에이전트가 이미 있다면 **Open**으로 돌아갑니다. 항목 상세에서 논의와 현재 상태를 읽고, 전체 GitHub 페이지가 필요하면 외부 링크를 사용하세요. GitHub 상태를 변경하기 전에는 저장소와 동작을 확인하세요.

[Diff](/ko/review-and-feedback)에서 에이전트의 변경과 검증 결과를 검토하세요. 실제로 받아들인 작업 결과에 맞게 이슈 상태를 관리합니다.

## 통합 설정

**Plugins → GitHub → Plugin settings**에서 선택한 작업 공간의 새로 고침 간격과 기본 이슈 목록 등을 설정합니다. 호환성과 설정 범위는 [플러그인](/ko/plugins)을 참고하세요.

원격 에이전트가 데스크톱 로그인으로 이슈를 읽으려면 별도의 [SSH GitHub 읽기 연결](/ko/remote-and-ssh#데스크톱-로그인으로-github-이슈-읽기)을 사용합니다. 로컬 사이드바와 지원 명령·접근 범위가 다릅니다.
