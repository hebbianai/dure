pane은 작업을 보여 주는 화면입니다. 관리되는 세션의 터미널과 제공자 프로세스는 별도 호스트가 소유합니다. 이 구조 덕분에 화면을 다시 열려고 새 대화를 만들 필요 없이 실행 중인 작업으로 돌아갈 수 있습니다.

## 기존 에이전트 열기

사이드바에서 에이전트를 찾아 pane을 여세요. Space나 화면을 바꿔도 세션의 작업 폴더와 대화는 유지됩니다.

세션 호스트와 컴퓨터가 실행 중이면 앱 연결이 끊겨도 관리되는 작업이 계속될 수 있습니다. Dure를 다시 열면 현재 화면과 이후 출력에 연결됩니다. 모든 제공자, 호스트, 컴퓨터가 모든 중단에서 복구된다는 보장은 아닙니다.

## 상태에 맞는 동작 선택

| 상황 | 다음 동작 |
| --- | --- |
| 화면은 닫혔지만 세션은 실행 중 | 기존 에이전트를 다시 열고 중복 작업을 만들지 않기 |
| 앱 연결이 끊김 | 세션 상태를 확인하고 기존 작업에 재연결하기 |
| 제공자나 호스트가 종료됨 | 해당 세션에 제공되는 복구 동작 확인하기 |
| 컴퓨터가 재부팅됨 | 원래 프로세스는 종료됨. 지원되는 복구는 새 프로세스를 만듦 |

pane 닫기, 에이전트 중지, 작업 파일 삭제는 서로 다른 동작입니다. 유지할 작업을 끝내기 전에는 동작 설명과 확인 내용을 읽으세요.

## Session Recovery 사용

**Session Recovery**에서 연결이 끊기거나 종료된 세션과 제안된 복구를 확인하세요. 확인 요청이 있으면 검토한 뒤 진행합니다. 복구 범위는 제공자의 재개 지원과 저장된 세션에 따라 달라집니다.

복구 후에는 명령을 다시 실행하기 전에 대화, 작업 폴더, 변경된 파일, 외부 시스템에 반영된 결과를 확인하세요. 복구가 이미 완료된 배포를 되돌리거나 모든 제공자의 대화를 재개해 주지는 않습니다.

## 파일과 대화의 연속성 구분

Git worktree에는 작업 파일과 브랜치 상태가 저장됩니다. 실행 중인 프로세스 자체는 아닙니다. 유용한 변경은 평소 흐름으로 커밋하세요. 중단 후에는 [변경을 검토](/ko/review-and-feedback)하고 SSH 작업이라면 [원격 연결 상태](/ko/remote-and-ssh)를 확인하세요.
