에이전트의 결과를 받아들이기 전에 바뀐 코드와 검증 근거를 확인하세요. Dure의 Diff 화면에서 대화 옆에 리뷰를 두고 진행할 수 있습니다.

## 올바른 worktree 열기

로컬 에이전트나 worktree의 **Diff**를 여세요. 브랜치의 분기점을 기준으로 비교하며 커밋하지 않은 변경과 새 파일도 포함합니다. 변경 파일을 선택해 diff를 읽으세요. 리뷰를 여는 것만으로 스테이징하거나 커밋하지 않습니다.

## 실행 가능한 피드백 보내기

1. 파일이나 diff 줄에 댓글을 작성합니다.
2. 무엇을 왜 바꿔야 하는지 설명하고 필요하면 기대 동작을 적습니다.
3. 대기 중인 댓글을 연결된 에이전트에게 보냅니다.
4. 전송 결과를 확인하고 다음 수정본을 검토합니다.

연결된 에이전트가 없어도 리뷰를 읽을 수 있습니다. 전송하려면 수신자가 확인되어야 하며, 오류가 났다면 피드백이 도착했다고 볼 수 없습니다.

## 검증하고 합치기

어떤 검증을 실행했는지 묻고 결과를 확인한 뒤 영향받는 동작을 직접 점검하세요. 커밋하거나 평소 Git 흐름으로 브랜치를 합치기 전에 수정된 diff를 검토합니다. 서로 다른 worktree도 충돌할 수 있으므로 통합 결과까지 확인하세요.

Diff나 소스 제어 창을 에이전트 옆 또는 다른 모니터에 둘 수 있습니다. 내장 Diff 리뷰는 로컬 worktree용입니다. [SSH 프로젝트](/ko/remote-and-ssh)의 변경은 원격 호스트의 Git으로 검토하세요.

이슈나 pull request에서 시작한 작업이라면 [GitHub](/ko/github-workflows)로 돌아가 현재 상태를 확인하세요.
