title: "VM 환경"

---

Dure는 저장소의 레시피로 worktree 전용 VM이나 컨테이너를 준비할 수 있습니다. 레시피를 로컬에서 실행하고 SSH 엔드포인트를 등록한 뒤, 그 환경 안에서 평소의 원격 프로젝트와 에이전트 흐름을 그대로 사용합니다.

VM 환경에는 Beta 인터페이스가 필요합니다. **설정 → 일반 → 인터페이스 모드**에서 **베타**를 선택하세요. Basic에서도 기존 환경을 일시 중지하거나 삭제할 수는 있지만, 새로 만들거나 재개할 수는 없습니다.

## 환경 사용하기

1. **에이전트 추가**에서 로컬 Git 프로젝트를 선택하고 **VM 사용 · Beta**를 선택합니다.
2. 레시피를 고르고 환경 이름을 정한 뒤 **환경 준비**를 선택합니다. 먼저 스크립트를 검토하세요. 스크립트는 로컬 자격 증명으로 실행되며, 제공자에서 비용이 청구되는 리소스를 만들 수 있습니다.
3. 환경이 실행 중이 되면 **이 환경에서 계속**을 선택합니다. SSH 호스트 키를 확인한 다음 평소처럼 브랜치를 고르고 원격 worktree를 만듭니다.
4. **설정 → VM 환경**에서 **일시 중지**, **재개**, **삭제**를 관리합니다.

대화상자를 닫아도 준비는 계속됩니다. 설정에서 실행 중인 환경을 열면 SSH 등록이나 에이전트 시작이 실패했을 때 복구할 수 있습니다. 에이전트를 삭제하거나 pane을 닫아도 환경은 삭제되지 **않습니다**. 보존할 작업을 저장하거나 푸시한 뒤 **삭제**를 명시적으로 사용하세요. 일시 중지하면 세션 연결이 끊기고, 삭제하면 게스트의 모든 파일이 사라질 수 있습니다. Dure는 실행 중인 프로세스를 옮기지 않으며, 제공자 로그인 자격 증명을 VM에 복사하지 않습니다.

## Lima로 로컬 VM 사용해 보기

[Lima](https://lima-vm.io/docs/installation/) 1.2 이상, Git, Python 3를 설치하세요. [Lima 레시피](https://github.com/hebbianai/dure/blob/main/docs/public/examples/lima/lima.sh)는 프로젝트의 `.dure/lima.sh`로, 그 [매니페스트](/examples/lima/dure.environments.json)는 프로젝트 루트의 `dure.environments.json`으로 저장합니다. 프로젝트 루트에서 다음을 실행하세요.

~~~bash
mkdir -p .dure
curl -fsSL https://raw.githubusercontent.com/hebbianai/dure/main/docs/public/examples/lima/lima.sh -o .dure/lima.sh
curl -fsSL https://docs.dureai.dev/examples/lima/dure.environments.json -o dure.environments.json
~~~

Dure는 레시피를 Bash로 실행하므로 스크립트에 실행 권한이 없어도 됩니다. 프로젝트에 이미 `dure.environments.json`이 있다면 파일을 덮어쓰지 말고 `environments` 목록에 `lima` 레시피를 추가하세요.

이 예제는 CPU 2개, 메모리 2 GiB, 디스크 12 GiB의 Ubuntu 24.04 VM을 사용합니다. 현재 커밋된 `HEAD`를 `/home/dure/project`에 복사하며, 커밋하지 않은 변경, 무시된 파일, 자격 증명은 포함하지 않습니다. 호스트 디렉터리는 하나도 마운트하지 않습니다. 에이전트 작업을 시작하기 전에 VM 안에서 에이전트 CLI를 설치하고 로그인하세요.

Lima가 [SSH 엔드포인트와 키](https://lima-vm.io/docs/usage/ssh/)를 제공합니다. 레시피가 루프백 포트를 고정하므로 다시 시작해도 같은 연결이 유지됩니다. 지원되는 Mac에서는 Lima가 [Apple 가상화](https://lima-vm.io/docs/config/vmtype/vz/)를 사용합니다. 비공개 준비 로그는 `LIMA_HOME`과 같은 위치에 있는 `<LIMA_HOME directory name>-dure-logs` 디렉터리에 기록됩니다. 기본값: `~/.lima-dure-logs`.

## 레시피 계약

프로젝트 루트에 `dure.environments.json`을 만드세요.

~~~json
{
  "schemaVersion": 1,
  "environments": [{
    "id": "my-vm",
    "name": "My VM provider",
    "create": ".dure/create.sh",
    "destroy": ".dure/destroy.sh",
    "suspend": ".dure/suspend.sh",
    "resume": ".dure/resume.sh"
  }]
}
~~~

`create`와 `destroy`는 필수입니다. `suspend`와 `resume`은 둘 다 지정하거나 둘 다 생략해야 합니다. 경로는 프로젝트 안의 파일로 해석되어야 합니다. 각 스크립트는 UTF-8이고 64 KiB 이하여야 하며, 매니페스트 하나에 레시피를 최대 32개까지 넣을 수 있습니다. 레시피 하나에서 캡처한 스크립트를 JSON으로 인코딩한 크기는 256 KiB 이하여야 합니다.

스크립트는 해당 환경 전용의 비공개 영구 작업 디렉터리에서 Bash로 실행됩니다. 원본 저장소는 `DURE_PROJECT_PATH`로 읽으세요. Dure는 생성 전에 선택한 스크립트 내용과 다이제스트를 캡처합니다. 선택한 뒤 스크립트를 바꾸면 레시피를 다시 불러와야 합니다. 이후 생명주기 작업은 프로젝트가 삭제된 뒤에도 캡처된 스크립트를 사용합니다. 정리 로직은 그 자체로 완결되게 만드세요. 원본 프로젝트의 보조 파일은 스냅샷에 포함되지 않습니다.

각 호출은 다음 환경 변수를 받습니다.

| 변수 | 의미 |
| --- | --- |
| `DURE_ENVIRONMENT_ID` | 준비 전부터 사용할 수 있는, 미리 할당된 고정 인스턴스 ID |
| `DURE_ENVIRONMENT_NAME` | 사용자가 정한 표시 이름 |
| `DURE_ENVIRONMENT_ACTION` | `create`, `suspend`, `resume`, `destroy` 중 하나 |
| `DURE_ENVIRONMENT_SCHEMA_VERSION` | `1` |
| `DURE_PROJECT_PATH` | 원래 로컬 프로젝트 경로 |

Stdin으로는 `schemaVersion`, `action`, `instanceId`, `name`, `projectPath`, `recipeResult`(마지막 성공 결과 또는 `null`)가 담긴 JSON 객체 하나가 들어옵니다. Dure는 이름이 `DURE_`, `HMUX_`, `GIT_`로 시작하는 상속 변수를 모두 제거한 뒤 위 변수를 설정합니다. 그 밖의 상속된 환경 변수는 제공자 CLI에서 사용할 수 있습니다. 준비 작업은 포그라운드에서 끝까지 실행하세요. 제한된 자식 프로세스는 작업 잠금을 상속합니다. 데몬이 그 디스크립터를 열어 두면 해제할 때까지 이후 생명주기 작업을 진행할 수 없습니다.

성공한 `create`와 `resume`은 stdout에 JSON 결과를 정확히 하나 출력해야 합니다.

~~~json
{
  "schemaVersion": 1,
  "resourceId": "provider-resource-id",
  "connection": {
    "host": "127.0.0.1",
    "port": 2222,
    "user": "developer",
    "keyPath": "/absolute/local/path/to/private/key",
    "projectRoot": "/absolute/guest/repository/path"
  },
  "userData": {}
}
~~~

`keyPath`는 선택 사항이며, 생략하면 일반적인 SSH 에이전트/설정 해석을 사용합니다. 게스트의 프로젝트 루트는 미리 존재해야 합니다. `userData`는 선택적 객체로, 이후 명령을 위해 비공개로 보관되며 클라이언트에는 반환되지 않습니다. 재개할 때는 같은 리소스 ID와 연결 필드를 반환해야 합니다. 클라우드 VM에는 고정 주소/포트나 DNS 이름을 사용하세요.

성공한 `suspend`와 `destroy`는 상태 코드 0으로 종료합니다. 모든 명령에는 30분 제한이 있고 출력은 64 KiB로 제한됩니다. 자세한 로그는 비공개 파일에 남기세요. Dure는 제공자 출력 없이 오류 코드만 표시합니다.

## 복구와 소유권

레코드는 준비 **전에** 저장됩니다. 생성이 실패하거나 잘못된 형식의 결과를 내면 캡처된 destroy 스크립트가 자동으로 실행됩니다. 제공자 리소스에는 `DURE_ENVIRONMENT_ID`로 레이블이나 이름을 붙여야 하며, `destroy`는 `recipeResult`가 `null`이거나 리소스가 이미 없어도 멱등이어야 합니다.

백엔드가 중단되면 실패한 레코드가 남습니다. 설정을 새로 고친 뒤 이를 삭제해 제공자 리소스를 정리하세요. Dure는 생성을 다시 실행하지 않습니다. 정리 실패는 재시도할 수 있도록 계속 표시됩니다. 같은 생성 키로 요청을 반복해도 환경이 추가로 만들어지지 않습니다. 로컬 백엔드당 최대 512개 레코드를 보관하며, 삭제된 레코드도 재시도 식별 정보를 유지합니다.

## CLI

~~~sh
dure environment recipes --project /absolute/repo
dure environment create --project /absolute/repo --recipe my-vm \
  --digest sha256:DIGEST_FROM_RECIPES --name task-42 --request-id task-42-vm
dure environment list
dure environment suspend --id ENVIRONMENT_ID --revision CURRENT_REVISION
dure environment resume --id ENVIRONMENT_ID --revision CURRENT_REVISION
dure environment destroy --id ENVIRONMENT_ID --revision CURRENT_REVISION
~~~

명령은 로컬 백엔드를 대상으로 하며 JSON을 반환합니다. 생성 요청은 대기 중인 레코드를 접수했다는 응답만 반환하므로 `list`로 완료를 확인하세요. 응답을 받지 못해 재시도할 때는 반환된 `requestId`를 그대로 사용하세요. 생명주기를 변경하기 전에 최신 revision을 읽으세요.
