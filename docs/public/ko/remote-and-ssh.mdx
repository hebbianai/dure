코드나 도구가 다른 컴퓨터에 있다면 SSH 프로젝트를 사용하세요. 로컬 작업 옆에 pane을 둘 수 있으며 표시된 호스트와 폴더에서 명령 실행 위치를 확인합니다.

## 연결하고 프로젝트 열기

1. **Remote Explorer**를 열고 **Add SSH host**를 선택합니다.
2. 호스트 정보를 입력하고 SSH 에이전트, 키 파일, 비밀번호 또는 기존 SSH 설정이 인증을 처리하는 경우 별도 자격 증명 없음을 선택합니다.
3. 연결한 뒤 원격 폴더를 탐색해 프로젝트를 추가합니다.
4. 그곳에서 셸이나 에이전트를 시작합니다. 해당 컴퓨터에 제공자 CLI와 로그인이 준비되어 있어야 합니다.

SSH 접근과 제공자 인증은 별개입니다. 명령을 실행하거나 독립 worktree를 시작하기 전에 원격 작업 폴더를 확인하세요.

## 원격 에이전트에 파일 전달

터미널에 이미지를 붙여넣거나 파일을 드롭하세요. Dure가 업로드를 마치면 원격 경로를 넣습니다. 준비가 끝난 뒤 요청을 보내세요. 자세한 내용은 [터미널 첨부](/ko/terminal-and-files)를 참고하세요.

## 재연결과 리뷰

호스트가 실행 중이면 기존 관리 세션에 다시 연결하세요. 원격 재부팅이나 프로세스 종료 뒤에는 [복구](/ko/session-model)가 필요하며 연속 실행으로 볼 수 없습니다. 중복 작업을 만들기 전에 상태를 확인하세요.

원격 호스트의 Git으로 변경을 검토하고 합치세요. 내장 Diff 리뷰는 현재 로컬 worktree를 대상으로 합니다.

## 데스크톱 로그인으로 GitHub 이슈 읽기

Dure가 GitHub SSH 프로젝트에서 시작한 에이전트는 `gh issue list`와 `gh issue view NUMBER --comments`를 사용할 수 있습니다. Dure가 데스크톱의 `gh` 로그인으로 조회하고 결과를 SSH로 반환합니다. 원격 컴퓨터에는 Python 3이 필요합니다. 원격 GitHub 로그인이나 데스크톱에 같은 저장소의 로컬 복사본은 필요하지 않습니다.

```sh
gh issue list --limit 20 --json number,title
gh issue view 123 --comments
gh issue view 123 --json title,body,comments
```

연결 범위는 프로젝트의 `github.com` `origin`입니다. `--repo`에는 같은 저장소만 지정할 수 있습니다. `--state`, `--label`, `--assignee`, `--author`로 필터링할 수 있습니다. `--search`는 고급 한정자나 불리언 연산자가 없는 일반 텍스트만 받습니다. 목록은 최대 100개이며 큰 응답은 `--json`으로 범위를 줄여야 합니다. 인증 명령, 쓰기, 다른 저장소, `--web`, 템플릿, `--jq`는 이 연결에서 지원하지 않습니다. 인증 오류가 나면 데스크톱에서 `gh auth login`으로 로그인하세요.

데스크톱 앱 연결을 유지하세요. 연결이 끊기거나 데스크톱이 재시작되면 Dure에서 에이전트를 새로 고쳐 연결을 복원합니다. 기존 에이전트도 새 명령 환경을 받으려면 새로 고침이 필요합니다. GitHub Enterprise와 Dure 밖에서 직접 시작한 에이전트는 이 통합에 포함되지 않습니다.

로컬 이슈와 pull request 작업은 [GitHub 사이드바 안내](/ko/github-workflows)를 참고하세요.
