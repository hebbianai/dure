정확한 오류와 선택한 프로젝트, 호스트, 제공자부터 확인하세요. 같은 작업을 반복해서 시작하기보다 오류 메시지를 남기는 것이 도움이 됩니다.

## 에이전트가 없거나 시작되지 않을 때

일반 터미널에서 해당 CLI를 실행해 보세요. **Settings → Provider**에서 감지와 설정 안내를 확인합니다. 셸의 `PATH`를 바꿨다면 Dure를 다시 열어 환경을 읽게 하세요. SSH 작업이라면 원격 컴퓨터에서 같은 확인을 진행합니다.

로그인이 필요하면 제공자 인증을 완료하고 계정에 해당 도구나 모델 접근 권한이 있는지 확인하세요. Dure가 제공자 자격 증명을 제공하지는 않습니다.

## GitHub 저장소가 없거나 접근 오류가 날 때

GitHub remote가 있는 로컬 Git 프로젝트를 선택하고 데스크톱 GitHub CLI를 확인하세요.

```sh
gh auth status
git remote -v
```

로그인한 계정이 저장소를 읽을 수 있는지 확인한 뒤 사이드바를 새로 고치세요. 조직이나 Projects 권한 오류에는 해당 GitHub 접근 권한이 필요합니다. [GitHub 작업](/ko/github-workflows)을 참고하세요.

## 설정이나 플러그인이 보이지 않을 때

Basic 인터페이스의 현재 위치는 [설정 안내](/ko/settings)를 확인하세요. 사이드바의 **Plugin**에서 호환성과 설정을 살펴보고 목록을 새로 고치세요. 거부되거나 충돌한 패키지는 활성 통합이 아닙니다. [플러그인](/ko/plugins)을 참고하세요.

## 작업 연결이 끊기거나 종료된 것처럼 보일 때

다른 사본을 실행하기 전에 [세션 상태](/ko/session-model)와 실제 파일을 확인하세요. 실행 중이면 재연결하고, 종료되었다면 제공된 복구 동작을 사용합니다. 에이전트가 외부 작업을 반복하지 않도록 완료된 내용을 기록하세요.

## 첨부가 전달되지 않았을 때

준비와 업로드가 끝난 뒤 전송하세요. pane의 호스트, 파일 경로, 전송 오류를 확인하고 실패한 첨부를 다시 시도합니다. 이미지 지원은 제공자별로 다릅니다. [터미널 첨부](/ko/terminal-and-files)를 참고하세요.

## 업데이트나 macOS 실행에 실패할 때

**Settings → General**에서 설치 버전을 확인하세요. 업데이트 확인이 실패했다면 **Check for updates**를 다시 시도하거나 [Dure 설치](/ko/install)의 공식 DMG를 사용하세요. 확인만으로 설치되지는 않습니다.

macOS 경고라면 공식 다운로드인지 확인하고 [Apple 안내](https://support.apple.com/en-us/102445)를 따르세요. 보안 기능을 끄거나 악성 소프트웨어로 표시된 파일을 강제로 열지 마세요.

## 유용한 오류 보고 만들기

앱 버전, 제공자와 CLI 버전, 로컬/SSH 여부, 정확한 동작과 오류를 포함하세요. **Settings → Privacy and telemetry**에서 검토 후 직접 저장할 수 있는 진단 보고서를 안내합니다. 공유 전에는 자격 증명, 비공개 경로와 관련 없는 대화를 제거하세요.
