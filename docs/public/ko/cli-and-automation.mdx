---
title: "CLI로 작업 실행과 예약"
description: "설치된 Dure CLI로 작업을 시작하고 세션을 확인하며 반복 실행을 예약합니다."
---

앱이 설치한 Dure CLI를 사용하세요. **Settings → Agent tooling**에서 도구 설정을 확인할 수 있고, `dure --help`는 설치된 버전의 명령을 설명합니다.

## 프로젝트 폴더에서 시작

```sh
dure run --provider codex --worktree docs-review "코드와 README를 대조해 검토해줘. 파일은 수정하지 마."
```

전용 worktree로 작업 파일을 분리합니다. 실행 호스트에 설치되고 로그인된 제공자를 선택하세요. `--project`나 `--path`를 생략하면 백엔드가 현재 작업 폴더를 해석합니다.

Dure의 pane으로 식별된 터미널 안에서 `--space`를 생략하면 현재 Space에 새 pane이 생깁니다. 해당 맥락이 없는 일반 터미널이나 CI에서는 화면 없이 실행됩니다. 화면 없이 실행되는 작업은 실행 호스트에 제공자의 채팅 런타임이 있으면 그 런타임을 사용하므로, 해당 호스트에 Dure 앱이 없어도 됩니다. 작업이 출력한 `agentId`로 `dure transcript <agent-id>`를 실행해 읽으세요. 같은 머신에서 연결된 앱이 작업을 넘겨받으면 터미널 세션으로 유지됩니다. 목적지를 지정하려면 연결된 Space의 정확한 이름이나 ID를 `--space`로 전달하세요.

## 추가 입력 전에 작업 확인

```sh
dure ls
dure run --help
dure schedule --help
```

`dure read`는 세션 화면을, `dure transcript`는 사용 가능한 대화 기록을 읽습니다. 목록이 반환한 세션과 작업 공간 식별자로 관리 세션을 선택하세요. 실행 시작이나 입력 전달에 성공했다는 응답이 작업 완료를 뜻하지는 않습니다.

SSH 백엔드도 함께 쓴다면 `dure ls --all-backends`로 설정된 모든 백엔드의 세션을 `BACKEND` 열이 있는 표 하나로 볼 수 있습니다. 연결할 수 없는 백엔드는 오류와 함께 표시되며 다른 백엔드의 결과를 가리지 않습니다. `--json`을 쓰면 각 세션에 `backendProfileId`가 포함됩니다.

## 시작한 에이전트 기다리기

에이전트가 자기 Dure 터미널 패널에서 `dure run`을 실행하면 새 Run은 그 에이전트를 부모로 기록합니다. 호출한 에이전트는 자식을 하나씩 폴링하지 않고 한 번에 기다릴 수 있습니다.

```sh
dure wait --children all --timeout 900 --json   # 모든 자식이 정리될 때까지
dure wait --children any --json                 # 첫 자식이 정리될 때까지
```

자식은 턴을 마치고 유휴 상태가 되었거나, 입력이나 승인을 기다리거나, 종료되었거나, 시작에 실패하면 정리된 것으로 봅니다. JSON에는 각 자식과 상태가 담기며, 종료 코드 1은 정리된 자식 중 조치가 필요한 것이 있다는 뜻입니다. `dure runs show <agent>`는 Run의 부모를 보여 줍니다. `--no-parent`로 연결 없이 시작하거나, `--parent <agent>`로 같은 백엔드의 다른 에이전트에 연결하세요. 채팅 런타임의 자식은 아직 기다릴 수 없으니 `dure transcript`로 읽으세요.

부모는 기다리지 않아도 결과를 받습니다. 터미널 자식이 턴을 마치거나, 입력이나 승인을 기다리거나, 종료되거나, 중지될 때마다 Dure가 부모의 받은편지함에 메시지 하나를 보내고 부모를 깨웁니다. 턴을 마쳤거나 종료된 경우에는 자식의 최종 응답과 그 안의 GitHub 풀 리퀘스트 링크가 함께 담깁니다. 각 결과는 Dure가 다시 시작되어도 한 번만 보내집니다. 부모 자신의 세션이 끝났다면 보내지 않습니다.

## 터미널에서 에이전트 사이를 이동

`dure tui`는 모든 Space의 에이전트를 상태, 계정, 프로젝트와 함께 보여 주며, 앱 없이 SSH에서도 사용할 수 있습니다. 에이전트를 선택하고 Enter를 누르면 연결됩니다. `Ctrl-\`를 누른 다음 `d`를 누르면 연결을 끊고 목록으로 돌아가며, 에이전트는 계속 실행됩니다. 해당 컴퓨터에 앱이 없으면 계정은 `unknown`으로, 프로젝트는 에이전트의 작업 폴더 이름으로 표시됩니다.

SSH 백엔드도 함께 쓴다면 `dure tui --all-backends`로 설정된 모든 백엔드의 에이전트를 `BACKEND` 열이 있는 목록 하나로 볼 수 있으며, Enter를 누르면 그 에이전트의 백엔드를 통해 연결됩니다. 연결할 수 없는 백엔드는 목록 아래에 표시되며 다른 백엔드의 에이전트를 가리지 않습니다.

## 맡은 작업 선언하기

여러 에이전트나 봇이 한 저장소에서 일할 때, 각자 맡은 작업을 선언해 두면 다른 쪽이 시작하기 전에 겹침을 확인할 수 있습니다.

```sh
dure claim --issue 245 --paths 'src/auth/**' 'docs/auth.md'
dure claims
dure claim --release
```

Dure 터미널 패널 안에서는 그 세션이 담당자가 되고 브랜치와 워크트리도 함께 기록됩니다. 패널 밖에서는 담당자 이름을 지정하세요: `dure claim engine-2 --issue 2 --paths 'Sources/Engine/**'`. `dure claim`은 같은 저장소에서 이슈, 브랜치, 워크트리가 같거나 경로가 같은 파일을 가리킬 수 있는 다른 선언을 보여 주고, 하나라도 있으면 종료 코드 3을 반환합니다. `--check`는 선언을 기록하지 않고 겹침만 확인하므로 봇이 시작하기 전에 검사할 수 있습니다. 선언은 권고일 뿐 아무것도 잠그지 않으며, 해제할 때까지 남아 있습니다. 셸이 경로 패턴을 펼치지 않도록 따옴표로 감싸세요.

## 반복 작업 예약

프로젝트 폴더에서 실행합니다.

```sh
dure schedule create --id daily-review --provider codex --cron "0 9 * * 1-5" --timezone Asia/Seoul "최근 변경을 검토하고 위험 요소를 알려줘. 파일은 수정하지 마."
dure schedule show daily-review
dure schedule runs daily-review
```

생성하면 지정한 시간대의 평일 오전 9시에 실행되도록 활성화됩니다. 예약만 저장하고 실행은 켜지 않으려면 `--disabled`를 추가하세요. 예약 실행은 독립된 Git worktree를 사용합니다. 예약으로 시작된 에이전트는 유휴 상태가 30분간 확인되면 휴면하며, 대화는 유지되어 다시 깨울 수 있습니다. 에이전트가 멈춘 뒤에는 커밋되지 않았거나 추적되지 않은 변경이 없고 모든 커밋이 이미 기본 브랜치에 있을 때만 worktree를 제거하며, 그렇지 않으면 유지합니다. 반환된 실행 키로 `dure schedule inspect`를 호출하면 저장된 보고서를 읽을 수 있습니다. Dure 앱이 있는 머신에서 예약 실행은 터미널 세션입니다. 서버나 VM처럼 Dure CLI만 있는 호스트에서는 제공자에게 그곳의 채팅 런타임이 있으면 화면 없는 실행처럼 채팅 런타임에서 시작되며, `dure schedule runs`가 해당 실행의 `dure runs show` 명령을 보여줍니다. 유휴 휴면과 worktree 제거는 터미널 세션에만 적용됩니다.

나중에 이력을 잃지 않고 잠시 멈추려면 `dure schedule show`가 보여 준 리비전으로 `dure schedule set daily-review --disabled --expected-revision N`을 실행하세요. `--enabled`로 다시 켭니다. 같은 명령으로 `--cron`, `--timezone`, `--name`, `--prompt`도 바꿀 수 있습니다.

실행 서비스와 컴퓨터를 사용할 수 있어야 합니다. 앱 화면을 닫는 것과 서비스를 중지하는 것은 다릅니다. 절전 중이거나 꺼진 컴퓨터에서는 작업이 정상적으로 실행될 수 없습니다.

## 원격 백엔드 선택

SSH 실행에는 설정된 백엔드 ID를 `--backend`로 전달하세요. 해당 백엔드가 프로젝트 경로를 해석하며 제공자도 그곳에 준비되어 있어야 합니다. 명시적인 권한 옵션은 `dure run --help`로 확인하고 작업에 맞게 선택하세요.

구조화된 메시지와 결정은 [에이전트 조율](/ko/orchestration)을 참고하세요.
