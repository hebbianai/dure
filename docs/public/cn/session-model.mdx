---
title: "返回工作与恢复会话"
description: "区分已保存的视图、运行中的会话和需要恢复的进程。"
---

面板是工作的视图。受管理会话的终端和提供商进程由独立主机持有。这让你无需为了重新打开视图而创建新对话，就能返回仍在运行的工作。

## 返回已有智能体

在侧栏找到智能体并打开面板。切换 Space 或视图时，会话的工作目录和对话可以保持不变。

会话主机和机器仍在运行时，应用断开连接后，受管理的工作可以继续。重新打开 Dure 会连接到当前屏幕和后续输出。这不保证所有提供商、主机或机器都能从任何中断中恢复。

## 根据状态选择操作

| 情况 | 下一步 |
| --- | --- |
| 视图已关闭，会话仍存活 | 重新打开已有智能体，不要启动重复任务 |
| 应用失去连接 | 检查会话状态，尝试重新连接已有工作 |
| 提供商或主机已结束 | 查看此会话可用的恢复操作 |
| 机器已重启 | 原进程已结束；受支持的恢复会创建新进程 |

关闭面板、停止智能体和删除工作文件是不同操作。结束需要保留的工作前，请阅读操作说明和确认内容。

## 恢复已结束的智能体

智能体的会话进程结束后，面板会直接显示恢复操作：

- **Resume session** 或 **Resume exact conversation** 在新进程中继续保存的对话。如果没有保存对话 ID，先从工作目录中找到的对话里选择一个。
- **Start fresh** 或 **New conversation** 在同一面板中开始新对话。已保存的对话历史会保留。
- **Open shell**（适用于本地智能体）将智能体面板替换为位于其工作目录的 shell。

如果任务的 worktree 已丢失，**Recreate worktree and resume** 会先恢复 worktree 再继续。要找回已没有面板的旧工作，打开侧栏的 **Sessions**，按会话名称、ID 或文件夹搜索，然后选择该会话在面板中继续。能恢复什么取决于提供商的恢复支持和保存的对话。

恢复后，在重复命令前检查对话、工作目录、文件变更以及对外部系统已产生的影响。恢复不能撤销已完成的部署，也不保证每个提供商的对话都可继续。

## 区分文件与对话的延续

Git worktree 保存任务文件和分支状态，不是运行中的进程。按正常流程提交有用的修改。中断后[审查变更](/cn/review-and-feedback)；SSH 工作还应检查[远程连接状态](/cn/remote-and-ssh)。
