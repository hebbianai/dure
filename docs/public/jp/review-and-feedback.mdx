エージェントの成果を受け入れる前に、変更されたコードと検証の根拠を確認します。Dure はレビューを別の diff ウィンドウで開くため、会話の隣に置けます。

## 正しい worktree を開く

ローカルのエージェントのペインのツールバーで diff アイコンをクリックします。ツールチップは **View diff in a new window** で、ブランチに変更があるとコミット済みと未コミットのファイル数を `C2 W1` のように表示します。レビューは別のウィンドウで開きます。ブランチの分岐点を基準に比較し、未コミットの変更と新規ファイルも含めます。変更ファイルを選んで diff を読んでください。レビューを開くだけでステージングやコミットは行いません。

## 具体的なフィードバックを送る

1. ファイルまたは diff の行にコメントを追加します。
2. 何をなぜ変えるのか、必要なら期待する動作を説明します。
3. 保留中のコメントを関連付けられたエージェントに送信します。
4. 送信結果を確認し、次の修正をレビューします。

関連するエージェントがなくてもレビューは読めます。送信には受信者が必要で、エラーが出た場合は届いたとは判断できません。

## 検証して統合する

実行した検証を尋ね、結果を確認し、影響する動作を試してください。コミットや通常の Git 手順による統合の前に、更新された diff を読みます。別の worktree でも競合は起こるため、統合結果も検証してください。

Diff やソース管理のウィンドウをエージェントの隣や別モニターに配置できます。内蔵 Diff レビューはローカル worktree 用です。[SSH プロジェクト](/jp/remote-and-ssh)ではリモートホスト上の Git で変更を確認します。

issue や pull request から始めた作業は、[GitHub](/jp/github-workflows)に戻って現在の状態を確認してください。
