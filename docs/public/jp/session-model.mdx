title: "作業への復帰とセッション復旧"
description: "保存された画面、稼働中のセッション、復旧が必要なプロセスを区別します。"
---

ペインは作業の表示です。管理セッションのターミナルとプロバイダープロセスは、別のホストが所有します。この分離により、画面を開き直すために新しい会話を作らず、動いている作業へ戻れます。

## 既存のエージェントに戻る

サイドバーでエージェントを見つけ、ペインを開きます。Space や表示を変えても、セッションの作業フォルダーと会話を維持できます。

セッションホストとマシンが稼働していれば、アプリの接続が切れても管理されている作業は継続できます。Dure を開き直すと現在の画面とその後の出力に接続します。すべてのプロバイダー、ホスト、コンピューターがあらゆる中断から復旧する保証ではありません。

## 状態に合った操作を選ぶ

| 状況 | 次の操作 |
| --- | --- |
| 画面を閉じたがセッションは稼働中 | 既存のエージェントを開き、重複したタスクを作らない |
| アプリの接続が切れた | セッション状態を確認し、既存の作業に再接続する |
| プロバイダーまたはホストが終了した | そのセッションで利用できる復旧操作を確認する |
| コンピューターを再起動した | 元のプロセスは終了済み。対応する復旧で新しいプロセスを作る |

ペインを閉じる、エージェントを停止する、作業ファイルを削除する操作はそれぞれ異なります。残したい作業を終了する前に、操作と確認内容を読んでください。

## Session Recovery を使う

**Session Recovery** を開き、切断・終了したセッションと提案された復旧を確認します。求められた場合は内容を確認して実行します。復元できる範囲は、プロバイダーの再開対応と保存されたセッションに依存します。

復旧後にコマンドを繰り返す前に、会話、作業フォルダー、変更ファイル、外部への影響を確認してください。復旧は完了済みのデプロイを取り消さず、すべての会話の再開を保証しません。

## ファイルと会話の継続を区別する

Git worktree はタスクのファイルとブランチ状態を保存するもので、実行中のプロセスではありません。有用な変更を通常の手順でコミットしてください。中断後は[変更をレビュー](/jp/review-and-feedback)し、SSH 作業なら[リモート接続状態](/jp/remote-and-ssh)も確認します。
