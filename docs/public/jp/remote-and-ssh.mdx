コードやツールが別のマシンにある場合は SSH プロジェクトを使います。ペインをローカル作業の隣に配置でき、表示されたホストとフォルダーからコマンドの実行場所を確認できます。

## 接続してプロジェクトを開く

1. **Remote Explorer** を開き、**Add SSH host** を選択します。
2. ホスト情報を入力し、SSH agent、キーファイル、パスワード、または既存の SSH 設定で認証する場合は明示的な認証情報なしを選びます。
3. 接続し、リモートフォルダーを参照してプロジェクトを追加します。
4. そこでシェルやエージェントを開始します。そのマシンにプロバイダー CLI とログインが必要です。

SSH アクセスとプロバイダー認証は別です。コマンドの実行や独立 worktree の開始前に、リモートの作業フォルダーを確認してください。

## リモートエージェントへファイルを渡す

ターミナルに画像を貼り付けるかファイルをドロップします。Dure はアップロードが成功してからリモートパスを挿入します。準備が終わるまで送信を待ってください。[ターミナルの添付](/jp/terminal-and-files)も参照できます。

## 再接続とレビュー

ホストが動いていれば、既存の管理セッションに再接続します。リモートの再起動やプロセス終了後には[復旧](/jp/session-model)が必要で、連続稼働とは見なせません。重複した作業を始める前に状態を確認してください。

リモートホスト上の Git で変更を確認し、統合します。内蔵 Diff レビューは現在ローカル worktree を対象とします。

## デスクトップのログインで GitHub issue を読む

Dure が GitHub SSH プロジェクトで開始したエージェントは、`gh issue list` と `gh issue view NUMBER --comments` を利用できます。Dure がデスクトップの `gh` ログインで読み取りを実行し、SSH 経由で結果を返します。リモートには Python 3 が必要ですが、GitHub ログインやデスクトップ上の同じリポジトリのコピーは不要です。

```sh
gh issue list --limit 20 --json number,title
gh issue view 123 --comments
gh issue view 123 --json title,body,comments
```

接続範囲はプロジェクトの `github.com` 上の `origin` です。`--repo` は同じリポジトリだけを指定できます。`--state`、`--label`、`--assignee`、`--author` で絞り込めます。`--search` は高度な修飾子や論理演算子を含まない通常のテキストのみ対応します。一覧は最大 100 件で、大きな応答は `--json` で絞る必要があります。認証コマンド、書き込み、他リポジトリ、`--web`、テンプレート、`--jq` は利用できません。認証エラーならデスクトップで `gh auth login` を実行してください。

デスクトップアプリの接続を維持してください。切断やデスクトップ再起動後は、Dure でエージェントを更新して接続を復元します。既存のエージェントも、新しいコマンド環境を受け取るには更新が必要です。GitHub Enterprise と Dure 外で直接起動したエージェントは対象外です。

ローカルの issue と pull request の作業は [GitHub サイドバーの案内](/jp/github-workflows)を参照してください。
