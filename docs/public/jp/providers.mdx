Dure はインストール済みのコーディングエージェント CLI とプロバイダーアカウントを使います。モデル、認証、課金はプロバイダーが提供し、Dure は作業の文脈と画面をまとめます。

## プロバイダーを準備して選ぶ

**Settings → Agent CLI** で検出結果と設定案内を確認します。通常のターミナルで動く CLI から始めてください。Basic インターフェースのランチャーでは Claude Code、Codex、Kimi Code を選択できます。**Settings → General → Interface mode** で **Beta** を選ぶと、Pi、Gemini CLI、OpenCode などほかの登録ツールも追加されます。

**⌘N → New agent** でプロバイダーを選びます。新規エージェントはネイティブのターミナルペインで開きます。Beta では **Settings → General → Default agent pane** を Chat にすると、対応する新規エージェントを Chat で開けます。コマンドの登録は、すべてのモデル、アカウント機能、会話操作への対応を意味しません。

## 利用できる機能を確認する

| 機能 | 確認すること |
| --- | --- |
| ターミナル | CLI がインストールされ、選択したフォルダーとホストで起動できる |
| チャット表示（Beta） | そのプロバイダーとランタイムで Terminal/Chat が表示される |
| 既存の会話 | プロバイダーが保存した会話記録を Dure が検出できる |
| 再開や分岐 | 選択した会話とプロバイダーが操作に対応している |
| アカウントプロファイル | そのプロバイダーにアカウント選択機能がある |
| 使用量 | プロバイダーが新しい情報を返している |

Beta では Claude Code、Codex、OpenCode、Pi に構造化チャットの統合があり、利用可否はインストールされたツールとランタイムにも依存します。ほかのツールはネイティブのターミナル表示で利用できます。

## アカウントを選ぶ

**Settings → AI provider accounts** で対応するアカウントプロファイルを追加します。開始時かアカウントコントロールから使用するアカウントを選んでください。統合に対応していないプロバイダーは通常のログイン設定を使います。

アカウント切り替えでは、プロバイダープロセスの再起動と会話の再開が行われる場合があります。切り替え案内とログイン要求を確認してください。ペインの移動ではアカウントは変わりません。リモートプロジェクトでは[リモートホスト](/jp/remote-and-ssh)にも設定が必要です。

## 使用量と上限を確認する

Claude と Codex の使用量コントロールは、プロバイダーが返した上限とリセット時刻を表示します。**Settings → Appearance → Status bar** で上部バーの表示を切り替え、**Stats and usage** で活動を確認できます。情報がない、または古い場合は、余裕があるとは判断できません。

**Settings → General → アカウントの自動復旧 · Beta**で、選択したサーバーの復旧を設定します。プロバイダーを選び、自動復旧を有効にして、使用を許可するアカウントを選択して保存してください。対応するChat会話は、Dureのウィンドウをすべて閉じてもサーバーがアカウントを切り替えて元のリクエストを続行します。共有ワークスペースへの参加だけで個人アカウントが提供されることはありません。

最近の使用量に余裕があるアカウントを優先しますが、使用量が不明または古くても許可したアカウントは試行できます。失敗や結果不明の試行は表示され、無条件に再送されません。後から届いた人の入力が優先されます。手動切り替えは引き続き利用でき、認証の失敗には対応が必要です。

`dure recovery get codex --backend SERVER --json`で設定と登録済みアカウントを、`dure recovery status AGENT_ID --backend SERVER --json`で復旧結果を確認できます。リビジョンを指定する設定変更や使用量の送信については`dure recovery help`を参照してください。コマンドは選択したサーバーに直接接続します。

既定のプロバイダーと権限は **Settings → General** で選べます。実際のタスクに合わせて設定してください。[worktree はサンドボックスではありません](/jp/current-limits#ファイル分離と権限)。
