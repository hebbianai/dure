---
title: "独立したタスクを並行して進める"
description: "タスクと worktree を分け、それぞれの成果と統合後の変更を確認します。"
---

タスクを互いに独立して進められるときに、並行作業を追加します。まず[一つのエージェント](/jp/quickstart)から始め、どの作業を切り出せるかを判断しましょう。

## 作業範囲を分ける

各エージェントに、目標、関連ファイル、期待する結果、検証方法を伝えます。例:

| タスク | 範囲 | 求める検証の根拠 |
| --- | --- | --- |
| 検索動作の実装 | 検索コードと単体テスト | 変更された動作と関連テストの結果 |
| インストール案内のレビュー | 文書のみ。アプリのコードは変更しない | 確認したコマンドと古い手順 |

共有する判断は会話の中で決めます。タスクが同じファイルに触れ始めたら、互いの作業を上書きする前に範囲を調整してください。

## タスクごとに worktree を作る

1. **⌘N** を押し、プロジェクトを選んで最初のタスクを説明します。
2. **Isolate in a dedicated worktree** を有効にします。検出されたプロジェクトのセットアップコマンドが新しい worktree で実行されます。実行しない場合は **Advanced** で **Run setup after creating** をオフにします。
3. エージェントを開始します。別の worktree で二つ目のタスクを開始します。
4. 同じ [Space](/jp/spaces-and-panes) にペインを並べます。

ペインの分割や移動は配置を変える操作です。worktree の作成やファイルの移動は行いません。編集前に各エージェントの作業フォルダーを確認してください。

worktree は作業ディレクトリとブランチを分けます。統合時に変更が競合することはあり、同じマシンの認証情報、プロセス、ポート、ネットワークアクセスは共有されます。

## レビューして統合する

各タスクの [diff](/jp/review-and-feedback) を開き、変更と検証結果を確認します。必要なフィードバックを送ってから、通常の Git ワークフローでブランチを統合します。重複する変更を解決し、統合結果も検証してください。

構造化されたメッセージや判断が必要なら、[エージェントの連携](/jp/orchestration)を使います。どの統合を使う場合も、人の目標と受け入れ基準を明確にしてください。
