---
title: "CLI から実行とスケジュール設定"
description: "インストール済みの Dure CLI でタスク開始、セッション確認、定期実行を行います。"
---

アプリがインストールした Dure CLI を使います。**Settings → Agent tooling** で設定を確認でき、`dure --help` でインストール済みバージョンのコマンドを読めます。

## プロジェクトフォルダーから開始する

```sh
dure run --provider codex --worktree docs-review "コードと README を照合してレビューしてください。ファイルは変更しないでください。"
```

専用 worktree がタスクのファイルを分離します。実行ホストにインストールされ、ログイン済みのプロバイダーを選んでください。`--project` や `--path` を省略すると、バックエンドが現在の作業ディレクトリを解決します。

Dure のペインとして識別されたターミナル内で `--space` を省略すると、現在の Space に新しいペインが開きます。その文脈がない通常のターミナルや CI では、画面なしで実行されます。明示的な配置先が必要なら、接続済み Space の正確な名前か ID を `--space` で指定します。

## 追加の入力前に状態を確認する

```sh
dure ls
dure run --help
dure schedule --help
```

`dure read` はセッション画面、`dure transcript` は利用可能な会話記録を読みます。一覧で返されたセッションとワークスペースの識別子で対象を選んでください。起動や入力配信の成功応答だけでは、タスクの完了を意味しません。

SSH バックエンドも使っている場合、`dure ls --all-backends` で設定済みのすべてのバックエンドのセッションを、`BACKEND` 列のある 1 つの表で確認できます。接続できないバックエンドはエラーとともに報告され、他のバックエンドの結果は隠れません。`--json` では各セッションに `backendProfileId` が含まれます。

## 起動したエージェントを待つ

エージェントが自分の Dure ターミナルペインから `dure run` を実行すると、新しい Run はそのエージェントを親として記録します。呼び出したエージェントは、子を 1 つずつポーリングせずにまとめて待てます。

```sh
dure wait --children all --timeout 900 --json   # すべての子が落ち着くまで
dure wait --children any --json                 # 最初の子が落ち着くまで
```

子は、ターンを終えてアイドルになったとき、入力や承認を待っているとき、終了したとき、または起動に失敗したときに落ち着いたとみなされます。JSON には各子とその状態が含まれ、終了コード 1 は落ち着いた子に対応が必要なことを示します。`dure runs show <agent>` で Run の親を確認できます。`--no-parent` で親を記録せずに起動し、`--parent <agent>` で同じバックエンド上の別のエージェントに紐づけます。チャットランタイムの子はまだ待てません。`dure transcript` で読み取ってください。

## 繰り返すタスクを設定する

プロジェクトフォルダーで実行します。

```sh
dure schedule create --id daily-review --provider codex --cron "0 9 * * 1-5" --timezone Asia/Seoul "最近の変更をレビューしてリスクを報告してください。ファイルは変更しないでください。"
dure schedule show daily-review
dure schedule runs daily-review
```

作成すると、指定タイムゾーンの平日 09:00 の実行が有効になります。保存だけして定期実行を有効にしない場合は `--disabled` を追加します。スケジュール実行は独立した Git worktree を使います。スケジュールで起動したエージェントは、アイドル状態が 30 分確認されると休止します。会話は保持され、再開できます。エージェントの停止後、未コミットや未追跡の変更がなく、すべてのコミットがデフォルトブランチに含まれている場合にのみ worktree を削除し、それ以外は保持します。返された実行キーで `dure schedule inspect` を呼ぶと、保存された報告を読めます。

履歴を失わずに後で一時停止するには、`dure schedule show` が示すリビジョンで `dure schedule set daily-review --disabled --expected-revision N` を実行します。`--enabled` で再開します。同じコマンドで `--cron`、`--timezone`、`--name`、`--prompt` も変更できます。

実行サービスとマシンが利用可能である必要があります。アプリ画面を閉じることとサービスを止めることは異なり、スリープ中や電源が切れたマシンでは通常どおり実行できません。

## リモートバックエンドを選ぶ

SSH 実行では `--backend` に設定済みのバックエンド ID を渡します。そのバックエンドがプロジェクトパスを解決し、プロバイダー設定も必要です。権限の明示指定は `dure run --help` で確認し、タスクに合わせて選びます。

構造化されたメッセージと判断は[エージェントの連携](/jp/orchestration)を参照してください。
