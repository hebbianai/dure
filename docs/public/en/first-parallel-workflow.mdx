---
title: "Work on parallel tasks"
description: "Separate editing work, keep the context visible, and review the combined result."
---

Add parallel work when the tasks can proceed independently. Begin with [one agent](/en/quickstart), then decide which work can be separated.

## Give each task a clear boundary

For each agent, name the goal, relevant files, expected result and verification. For example:

| Task | Scope | Evidence to request |
| --- | --- | --- |
| Implement search behavior | Search code and its unit tests | The changed behavior and relevant test results |
| Review installation guidance | Documentation; no application edits | Commands checked and outdated instructions found |

Keep shared decisions in the conversation. If the tasks begin touching the same files, adjust their scopes before they overwrite each other's work.

## Create independent working folders

1. Press **⌘N**, choose the project and describe the first task.
2. Enable **Isolate in a dedicated worktree** and review its folder/setup choices.
3. Start the agent. Repeat for the second task with a different worktree.
4. Arrange the panes side by side in the same [Space](/en/spaces-and-panes).

Splitting or moving a pane changes the layout. It does not itself create a worktree or move files. Check each agent's working folder before it edits.

Worktrees have separate working directories and branches. They can still produce conflicting changes, and they share the machine's credentials, processes, ports and network access.

## Review and combine the work

Open each task's [Diff](/en/review-and-feedback), read the changes and check its verification. Send specific feedback before combining the branches with your normal Git workflow. Resolve overlaps and run checks on the combined result.

Use [agent coordination](/en/orchestration) when tasks need structured messages or decisions. Keep the human goal and acceptance criteria clear whichever integration you use.
